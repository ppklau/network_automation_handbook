# 01 — Introduction

## Purpose

Set the context for the handbook: what it covers, who it is for, how to navigate it, and the principles that guided its creation.

## Audience

All readers — this is the starting point regardless of role.

## Content Outline

### Why This Handbook Exists
- The gap in network automation is not tooling knowledge — it is the transformation journey
- Existing resources teach tools; this handbook guides organisations
- Consolidates practitioner experience into a cohesive, opinionated guide

### What This Handbook Is Not
- Not a vendor product guide
- Not a single-tool tutorial
- Not a theoretical framework disconnected from implementation

### How to Use This Handbook
- Reading paths by role (Executive, Engineer, Transformation Lead)
- Each chapter is self-contained but cross-referenced
- Templates and examples are designed to be immediately usable
- Progressive complexity within each chapter

### Content Principles
- Practical over theoretical
- Vendor-neutral
- Business-linked at every stage
- People-first transformation mindset
- Pragmatic buy vs build decisions
- Product thinking applied to automation itself
- Security and compliance woven through, not bolted on

### The ACME Investments Example
- Fictional financial services firm used throughout the handbook
- Provides a consistent, realistic context for examples
- Spans datacenter (Arista EOS spine-leaf) and branch office (Cisco IOS) environments
- Subject to regulatory pressures (MiFID II, FCA, PCI-DSS)
