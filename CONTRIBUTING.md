# Contributing to the Network Automation Handbook

Thank you for your interest in contributing to this project.

---

## How to Contribute

### Reporting Issues

If you find errors, outdated information, or areas that need improvement, please open an issue with:

- A clear description of the problem
- The chapter or file affected
- A suggested correction if you have one

### Suggesting Content

If you have ideas for new sections, templates, or examples, open an issue with the tag `content-suggestion` and include:

- What the content would cover
- Which chapter it belongs in
- Why it would be valuable to readers

### Submitting Changes

1. Fork the repository
2. Create a feature branch (`git checkout -b improve-chapter-03`)
3. Make your changes
4. Ensure your content follows the style guidelines below
5. Submit a pull request with a clear description of what you changed and why

---

## Style Guidelines

### Writing

- Write in British English (consistent with the existing content)
- Use active voice where possible
- Be practical and specific — avoid vague generalities
- Every technical recommendation should include a "why" and a "when to use"
- Keep paragraphs focused — one idea per paragraph

### Formatting

- Use Markdown for all content
- Use `##` for main sections within a chapter, `###` for subsections
- Code examples should be in fenced code blocks with language identifiers
- YAML examples should be realistic and self-consistent
- Diagrams should be in Mermaid format where possible (renders natively on GitHub)

### Templates

- Templates should be immediately usable — not abstract frameworks
- Include example data that is realistic (use the ACME Investments context where appropriate)
- Provide instructions for how to adapt the template to a real environment

### Business Alignment

- Every technical section should include a business value statement
- Use the four value pillars: cost reduction, risk reduction, agility/speed, service quality
- Include metrics or KPIs where possible

---

## Content Structure

Each chapter follows a consistent structure:

1. **Chapter README.md** — overview, objectives, audience guidance
2. **Content files** — the substantive material, broken into logical sections
3. **Cross-references** — links to related chapters, templates, and examples

---

## Code of Conduct

Be respectful, constructive, and professional. This is a practitioner community — we value experience, honesty, and practical wisdom over credentials or theory.
